# 文字牌型與輔助填入測試版

## 保持原操作

貼文字 →「貼上並建立審核」→ 原預覽／必要時編輯及重新解析 →
「輔助填入」→ 核對表單。沒有自動送出。

預覽現在顯示完整柱群、各星倍率及金額、彩種。文字或彩種變更後必須重新解析，
舊結果不可繼續填。既有「已下牌」仍須使用者明確按下，才反灰及計入完成。
本機通過不代表真站已驗收。

## 可貼的合成範例

以下不是客戶牌單；預期值使用既有產品規則（1 支 = 100 元）。

| 牌型 | 可貼文字 | 明確預期 |
|---|---|---|
| 一般、多倍率 | `01 12 23 2×5 3×0.5` | 二星500元、三星50元，同一組號碼 |
| 不等高柱碰 | `01 × 12 × 23 33 2×3 3×1` | 三柱 [01] [12] [23,33]；300／100元 |
| 小數、LINE 分隔 | `01　12，23 2/3X0.1` | 二三星各10元，不將類別當投注號碼 |
| 尾（539） | `02 × 13 × 6尾 2,3×0.5` | 最後一柱依既有尾規則為06,16,26,36；各50元 |
| 車 | `01車1` | 解析保留；現有欄位未對應，不可輔助填入 |
| 半車 | `01半車` | 0.5車；不可輔助填入 |
| 各半車 | `01 12 各半車` | 兩筆各0.5車，保留共同原文；不可輔助填入 |
| 各N車 | `01 12 各2車` | 兩筆各2車；不可輔助填入 |

緊接同筆號碼的倍率續行可以貼：

```text
01 × 12 × 23 33 2×3
3×1
```

空白行或新說話者會中斷這個新增的「已帶倍率投注 → 下一條倍率」scope。
獨立 `3×5` 仍依既有合法單號車簡寫解析，不全域禁用。
多筆共用倍率若沒有既有明確 scope，不能猜「同上」涵蓋哪幾筆。
請使用每筆完整寫出倍率的既有格式；本輪沒有發明跨筆共用語法。
例如 `01 12 23 二星` 是缺倍率；不補1。`?尾`、衝突倍率、
未知特殊玩法仍留在人工確認區。「全部同上」不能當成姓名丟掉。

同內容的兩筆投注保留兩筆。雙擊／同一請求重送不會再次填入；
既有「重新填入」按鈕才建立新操作。逾時或部分失敗保留「結果未明」，
沒有背景自動重試，也不顯示成功。

## 本機啟動

在此 worktree 執行：

```powershell
python tools/run_text_local.py --port 8766
```

開啟 http://127.0.0.1:8766/assist-panel 。按輔助填入後另開本機測試表單。
8765 舊程式不會被切換或停止。此入口僅允許文字驗收路由，
瀏覽器拒絕外部網路請求，圖片模型路由關閉。
需要既有 Python 3.11、pytest、Playwright 與 Chromium，不新增模型。

一般／柱碰會讀回完整號碼、全部星別金額（含不應殘留的星別）與明確 GameID。
不一致或無法取得讀回證據時報錯。真站必須由真人確認現有 B03 欄位及 GameID
契約仍相符；無證據時本版會拒絕填入，不假稱完成。

## 測試與基線

```powershell
python -m pytest tests/test_text_operation_contract.py tests/test_text_fill_browser_contract.py
python -m pytest tests/test_assist_panel_e2e.py tests/test_manual_reparse_registry.py
```

獨立分支以實際最後使用的 region-review worktree 為基線；一併保留該版本已存在、
尚未提交的文字保真修復（含車數單位轉寫與來源分層相容性），未調模型、提示詞、
辨識路由或執行模型測試。

原有3個 UI 測試期待填入即自動完成，但實際既有流程有「已下牌」人工按鈕。
修正測試為先證明未自動完成，再明確按下；完成反灰與原有清除計數一併接通。
另有實際瀏覽器表單讀回測試，不用 mock 的 ok=true 代替欄位核對。

## 本輪稽核結論

- 原本可解析：一般牌、柱碰、尾、明確每星倍率、單號車、明確各車數。
- 已修復操作斷點：編輯後柱群被壓平、預覽缺少各星金額、柱碰填入漏掉多倍率、
  一般／柱碰未核對完整讀回、同秒批次覆寫、重複請求與舊解析結果可再次填入。
- 保留待確認：未知尾數、缺倍率、同星衝突倍率、未定義的跨筆「全部同上」、
  多個號碼但沒有「各」等明確特殊玩法作用範圍。
- 已支援解析、尚未支援真實欄位：車系列。合成 mock 金額正確不等於該玩法已能真站填入。

測試分開記錄：合成 parser／預覽單元測試、loopback 實際瀏覽器填入讀回、
既有封存文字離線重播。離線重播只檢查舊語意契約未變，不將有矛盾的舊人工資料
重新升格為 truth，也不衡量 OCR 準確率。沒有真人操作時間或真站驗收數據。
